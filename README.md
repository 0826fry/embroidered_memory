# EMBROIDERED MEMORY — v2

사진 위에 텍스트를 입력하는 대신, 사진의 색으로 실을 만들어 한 땀씩 수놓고 다시 풀어내는 인터랙티브 웹사이트입니다.

> Every stitch becomes part of the image. Even when the thread is removed, its trace remains.

- 배포 대상: <https://0826fry.github.io/embroidered_memory/>
- 기존 저장소: <https://github.com/0826fry/embroidered_memory>
- 기술: **HTML / CSS / Vanilla JavaScript / Canvas 2D**. 외부 라이브러리·CDN·빌드 과정 없음.
- 배포 폴더에는 **`index.html`, `style.css`, `script.js`, `README.md`** 네 파일만 있으면 됩니다. 자수는 procedural 방식이므로 추가 텍스처 파일은 필요하지 않습니다.

## 2. 사용하는 방법

1. `UPLOAD AN IMAGE`를 클릭하거나 사진을 끌어다 놓습니다.
2. 사진의 **빈 곳을 클릭**해 시작 지점을 정합니다.
3. 영문을 입력하면 글자 하나가 봉제됩니다. **애니메이션이 완전히 끝나야** 다음 키를 입력할 수 있습니다. 애니메이션 도중 친 키는 대기열에 쌓지 않습니다.
4. 한글은 한 음절을 조합하는 동안 흰색 임시 글자로만 보입니다. `Space` 또는 `Enter`를 눌러 수놓습니다.
5. 글자 위를 클릭하면 해당 글자가 **선택**됩니다. 상단 패널 슬라이더로 해당 글자만 수정하거나 `Delete`로 제거합니다. 빈 공간을 클릭하면 새로운 위치에서 작성합니다.
6. 마우스를 화면 상단으로 이동하면 설정이 나타납니다. `EXPORT PNG`로 결과를 저장합니다.

### 키보드 동작

| 동작 | 결과 |
|---|---|
| 영어 `A` 입력 | 즉시 `A` 봉제 애니메이션 |
| 한글 `정` 입력 | `ㅈ` / `저` / `정` 조합을 흰색 임시 글자로 보여줌. 자동 봉제 없음 |
| 한글 초안 + `Space` | **첫 번째 완성 음절 하나만** 봉제, 자동 공백 없음 |
| 초안 없는 `Space` | 실제 띄어쓰기 |
| 한글 초안 + `Enter` | 한 음절 봉제 완료 후 다음 줄 |
| 초안 없는 `Enter` | 다음 줄 |
| 조합 중 `Backspace` | IME의 자모 수정 기능 우선. Undo가 끼어들지 않음 |
| 미확정 초안 있는 `Backspace` | 일반 문자 삭제 |
| 초안 없는 `Backspace` | 마지막 완성 자수 글자 제거 |
| `Esc` | 미확정 초안 또는 선택 취소 |
| 완성 자수 클릭 + `Delete` | 해당 글자만 역방향으로 풀어 제거 |
| `Ctrl/Cmd + Z` | 마지막 완성 자수 글자 제거 (일반 Undo 대신 'un-stitch') |

**한글 예시:** `기` → Space → (기 자수 완성) → `억` → Space → (억 자수 완성). 이후 초안이 없는 상태에서 Space를 누르면 실제 띄어쓰기가 들어갑니다.

### 설정 패널

- **SIZE:** 사진 좌표 기준 글자 크기(24–160px). 선택한 글자의 크기를 조절하면 같은 줄의 뒤 글자들이 너비 변화만큼 이동합니다.
- **DENSITY:** 실제 자수 마스크의 스캔 간격·스티치 간격·스티치 수를 바꿉니다.
- **COLOR MATCH:** 배경색과 자수의 명도 차이를 조절합니다(값이 높을수록 더 비슷한 색).
- **COLOR VARIATION:** 대표 색상과 각 스티치의 주변 색상 사이 블렌드 정도를 조절합니다(값이 높을수록 국소적 색 변화가 큼).
- **PHOTO VIEW:** `FILL SCREEN`(cover) / `FIT IMAGE`(contain). 사진 자체는 자르지 않습니다.
- **THREAD CONNECTION:** 연결 실 표시 ON/OFF. OFF도 연결 데이터를 지우지는 않습니다.
- **UNDO LAST / DELETE SELECTED:** 글자별 제거. **바늘구멍은 남습니다.**
- **CLEAR ALL:** 사진은 유지하며 **모든 글자·연결 실·바늘구멍을 삭제**합니다.
- **NEW IMAGE:** 사진까지 지우고 업로드 화면으로 돌아갑니다.
- **EXPORT PNG:** 편집 도구·커서·선택 테두리·임시 글자는 제외합니다.

설정을 수정할 때 글자가 선택되어 있으면 **선택한 글자에만** 변경사항이 적용됩니다. 아무것도 선택되지 않은 상태에서는 **이후 생성할 글자**에 적용됩니다. 선택 글자 변경 시 실제 스티치와 인접한 연결 실을 다시 계산합니다.

## 3. 코드의 실제 동작

기존 프로젝트의 기본 원리를 보존했습니다.

- `maskCanvas`에 글리프 모양을 그린 후, 불투명 영역을 행별로 스캔하여 작은 대각선 satin stitch 조각을 생성합니다.
- 각 스티치는 **시작점, 끝점, RGB 색상, 실 굵기, 생성 순서**를 독립적으로 가집니다. 스티치 코어, 그림자, 하이라이트를 세 번의 별도 선으로 그립니다.
- `baseCanvas` 픽셀에서 각 스티치 중심의 5×5 근방을 색상 차이에 따라 가중 샘플링해 색 경계를 최대한 유지합니다.
- 글자 `Character Object`는 ID / 한 글자 내용 / 사진 좌표 / 크기·밀도·색 옵션 / seed / 생성 순서 / 스티치 배열을 가집니다.
- `Thread Connection`은 앞·뒤 글자 ID / 실제 첫·마지막 스티치를 연결하는 2차 베지어 곡선 / **앞 글자의 마지막 스티치 색**을 가집니다.
- 제거할 때에는 스티치를 역순으로 감추면서 짧은 풀리는 실을 표시하고, 스티치 끝점에서 생성한 `Needle Hole` 객체를 사진에 영구 합성합니다. 삭제된 글자에 연결된 실은 함께 제거하며 중간 글자 삭제 후 인접 글자를 임의로 재연결하지 않습니다.
- 입력은 별도의 native `<textarea>`로 받아 `compositionstart`, `compositionupdate`, `compositionend`, `beforeinput`, `input`, `keydown`을 처리합니다. 특히 한글 `compositionend`만으로는 확정하지 않습니다.
- 애니메이션은 `requestAnimationFrame`이며, `isAnimating` 동안 텍스트 필드가 비활성화되고 다른 키 입력도 차단됩니다. 원본 이미지는 현재 장면 캐시와 별도로 관리합니다.

### 좌표 / 이미지 품질

편집 좌표는 사진의 전체 픽셀 영역을 기준으로 저장합니다. 큰 사진은 작업 속도를 위해 긴 변 **최대 2000px**의 내부 작업 좌표계를 사용하며, 비율만 줄이므로 실제 원본 파일을 크롭하지 않습니다. 화면에서는 `cover/contain` 투영을 적용합니다.

원본 파일의 Blob은 가능하면 브라우저의 `IndexedDB`에 저장하고, 로컬 프로젝트 메타데이터와 복원용 소형 JPEG를 `localStorage`에 보관합니다. 일반적인 PNG 내보내기는 **원래 파일의 전체 폭·높이**로 재합성합니다. 기기나 브라우저에서 초대형 PNG 캔버스를 할당할 수 없는 경우 전체 사진의 내부 작업 해상도로 낮추어 다시 시도합니다.

### 저장 및 기존 데이터

- 프로젝트 메타데이터: `localStorage['embroidered-memory-v2']`.
- 원본 이미지: IndexedDB `embroidered-memory-assets / assets / photoId`.
- 구버전: `localStorage['embroidered-memory-v1']`.
- 마이그레이션: 새 저장 내용이 없고 옛 데이터가 있으면, 기존 문자열 오브젝트를 grapheme(글자)별로 나누어 자수 오브젝트로 변환합니다. **v1 키를 삭제하지 않고 유지**하므로 예전 버전으로 돌아갈 여지가 있습니다. 기존 단색도 가능하면 유지됩니다.
- 저장 형식에는 글자 seed / 사진 좌표 / 스티치 설정이 들어가며, 복원 시 **결정론적 방식으로 같은 스티치 좌표와 색상을 재구성**합니다. 실 연결과 바늘구멍 객체는 별도로 저장됩니다.
- 이미지 데이터가 매우 크거나 브라우저가 저장을 금지해도 편집은 계속됩니다. 하지만 **저장 실패 시 새로고침 복원이 보장되지는 않습니다.** 내보내기 버튼으로 작품을 보관하세요.
- IndexedDB를 사용할 수 없어 작은 복원용 JPEG만 남은 경우에는 좌표계를 그대로 복원하지만, 색이나 PNG 세부 화질은 원본 저장이 성공한 경우보다 낮을 수 있습니다.

## 4. GitHub Pages에 적용하는 방법

이미 GitHub Pages가 설정된 저장소이므로 새로운 프레임워크나 workflow를 구성할 필요가 없습니다.

1. 현재 저장소의 파일을 백업하거나, 가능하면 새 브랜치 `embroidered-memory-v2`에서 먼저 확인합니다.
2. 이 ZIP에 담긴 **4개 파일**을 기존 저장소 **최상위(root)** 의 동일한 이름 파일에 덮어씁니다.
3. 변경을 commit & push 합니다.
4. 저장소 **Settings → Pages → Build and deployment → Deploy from a branch**에서 `main` / `/(root)`를 선택합니다(이미 설정되어 있다면 유지).
5. `https://0826fry.github.io/embroidered_memory/`로 접속해 새로고침하여 동작을 확인합니다.

터미널을 사용한다면 저장소 폴더에서 다음처럼 적용할 수 있습니다(덮어쓸 파일을 확인한 뒤 실행).

```bash
git checkout -b embroidered-memory-v2
# 이 ZIP의 index.html, style.css, script.js, README.md를 저장소에 복사
git add index.html style.css script.js README.md
git commit -m "Enhance embroidery editor with character stitches and unstitching"
git push -u origin embroidered-memory-v2
```

검토 후 GitHub에서 pull request로 `main`에 병합하면 기존 Pages가 업데이트됩니다.

## 5. 테스트 및 현재 검증 범위

2026-10-13, Linux의 **headless Chromium 144**에서 HTML/CSS/JS를 페이지에 주입하여 시뮬레이션 기반 기능 테스트를 실행했습니다. 이 실행 환경에서 `localhost`, `file://` 등 브라우저 직접 탐색이 정책상 차단되어 **실제 GitHub Pages URL 접속 테스트와 정상 오리진 IndexedDB 테스트는 수행하지 못했습니다**. `localStorage`는 테스트용 API 대체 객체로 복원 흐름을 검증했습니다.

**테스트 통과:** 업로드 전/후 화면, 영어 즉시 글자 단위 봉제, 봉제 도중 새 키 무시, 한글 ㅈ→저→정 ghost preview, 합성 Space로 한 음절만 확정, 합성 Enter로 한 음절 확정 후 줄바꿈, 빈 초안 Space/Enter, 색상 경계 위 스티치별 색 변화, 연결 실 색/끝점, 개별 글자 설정 변경, 실제 스티치 개수에 영향을 주는 밀도 조절, 중간 글자 삭제 시 연결 정리, 역순 삭제 후 실제 스티치 끝점에 대응하는 바늘구멍, 화면 크기 변경 시 좌표 유지, 소스 이미지 전체 크기 PNG 다운로드, 저장 상태 복원, v1 데이터 마이그레이션.

**아직 직접 검증하지 못한 항목:** macOS **Safari 및 Chrome의 운영체제 실제 한글 IME** 키 이벤트 순서, iPhone/Android 실제 가상 키보드, 정상 사이트 오리진에서의 IndexedDB 이미지 복원, 대용량 스마트폰 사진의 극한 메모리 상황. 입력 코드는 합성 이벤트 경로를 반영했지만, **실제 Safari에서의 한글 단축키 동작까지 테스트가 끝났다고 단정하지 않습니다.** 배포 후 해당 기기에서 한글 `정`을 입력하고 Space/Enter 한 번으로 정확히 한 글자가 확정되는지 확인하는 것을 권장합니다.
